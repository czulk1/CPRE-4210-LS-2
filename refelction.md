# Reflection

This project is very different from anything that I have really done before. This is because I personally do not like using AI for coding or anything that requires more thought and work. I always feel as though, while it is faster to use AI to solve these problems, I often do not learn much about how what I have just implemented works or the specifics and details of the code. I like using AI as a way of giving ideas on how things should be formatted and how ideas could be handled. Using it to actually take over a problem is something that I have not done ever before. That is why, in my experience with this project, I felt weird doing it. Using these powerful tools like AI as sole developers with things like this can lead to issues, but if used responsibly, it can be powerful. The issues lie in where to draw that line of responsibility. Personally, I have always drawn that line before full development of an app, but here, for the project, I am required to. It led to an experience where I felt as though the project went perfectly fine, and it turned out wonderfully. I do not feel as though I have gotten much out of it myself. Which brings me to the second question of how did this deepen my understanding of this topic of overflows. Through class and my own research, I feel as though I had a good understanding of the topic, being buffer overflow and also algorithm overflow. There is something that this does for me, though. This is designed in such a way that it is very clear as to what happens in a buffer. The clear distinction in buffer size and to where the overflow would start to happen is fantastic for education on the specifics of buffer overflow. The visual of seeing where the characters start to go into the different buffers is a great way to see the implications of the small unprotected buffer. Also, this shows where the overflow starts to have large impacts, as we start to see when we will have a stack pointer overflow and some of the impacts of that being overwritten. Then, it also shows how and when you would start to overwrite the return address and the severity of this action. For this program, my workflow started with working with the Gemini AI by giving it the instructions and requirements for this assignment, then describing what I wanted from the program and how it should function. Afterward, I went through a series of iterative process working with the AI to generate what I wanted from the project. I reviewed the code, verified the memory regions mapped correctly to a standard 32-bit stack architecture (Buffer -> SFP -> Return Address), and tested the UI.
